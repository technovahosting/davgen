Cuando la BD cambie después

davgen sincronizar compara el esquema contra la última generación: si no cambió termina al instante; si cambió, regenera y sube a la nube SOLO los archivos afectados.

⑥ Reglas de oro

1 · El código generado NO se edita. Se REEMPLAZA al regenerar (carpetas con _NO-MODIFICAR.md). Si alguien editó algo, davgen lo respalda en _backendGenerado\_respaldo-ediciones\ antes de sobrescribir — pero la personalización va en clases que EXTIENDEN los services, en páginas propias y en App.jsx.
2 · La administración es por BASE DE DATOS. Roles (tbl_seg_rol), permisos (tbl_seg_permiso), menú (tbl_seg_modulo) y parámetros como 2FA obligatorio (tbl_seg_parametro): se editan ahí, sin regenerar.
3 · Tablas: el usuario crea SOLO tablas de negocio (tbl_{modulo}_* + vista vis_*); las de seguridad/autenticación ya existen y no se tocan (ver 02-Base-de-datos\readme_cero.md).

⑦ Pruebas y despliegue

Smoke test E2E (generado)

cd 05-Testing\generados
.\pruebas-api.ps1                                  # backend local
.\pruebas-api.ps1 -Api https://{dominio}/servicio/api   # nube

También se genera postman_collection.json (importar en Postman: el Login guarda el token solo) y api.http.

Despliegue a la nube (FTP)

davgen generar --produccion si --front si
  • Primera vez: sube el Laravel completo (zip) y lo extrae en el servidor; el frontend se construye y sube a la raíz.
  • Siguientes: sube SOLO el delta del código generado (segundos). davgen sincronizar --si --produccion si automatiza todo el ciclo.

⑧ Módulos activos — flags de [generar]

En modo interactivo, el generador muestra un menú de toggles antes de arrancar. Los cambios se guardan en _configtotal.ini y persisten en la próxima ejecución. Con --si se omite el menú.

FlagPor defectoQué generaCuándo activar
aplicar_sps✓ activo Compara y ejecuta los SPs pcru* en la BD (DROP+CREATE solo los nuevos o distintos) Siempre — mantiene los SPs sincronizados sin ejecutar el SQL a mano
produccion✓ activo Despliega el backend Laravel a la nube por FTP (zip completo la primera vez; delta incremental las siguientes) Cuando [ftp] está completo y se quiere desplegar
front✓ activo Ejecuta npm run build y sube dist/ a la raíz del FTP. Omite el build si las fuentes no cambiaron. Cuando [ftp] está completo y hay proyecto React
form_requests☐ desactivado app/Http/Requests/{Tabla}Request.php con reglas 422 derivadas del esquema (required/nullable, max:N, in: enum, email) Cuando se quiere validación automática en el servidor antes del SP
tests☐ desactivado Suite PHPUnit: AuthTest (422/401), RutasTest (401 por tabla), RateLimitTest (429) + tests/Datos/{Tabla}Datos.php Para ejecutar php artisan test en CI o antes de desplegar
componentes_react☐ desactivado Hooks useCrud/useAuth + componentes DataTable, CampoFormulario, SelectRelacion (FK como dropdown), Paginacion en src/hooks/ y src/components/generados/ Para UI más rica; los campos *_id usan SelectRelacion automáticamente
ci☐ desactivado .github/workflows/ci.yml: test PHP, build React y davgen verificar (rompe el build si se editó lo generado) Para proyectos con GitHub Actions
openapi☐ desactivado openapi.json (OpenAPI 3) + swagger.html (Swagger UI) en _backendGenerado/documentacion/ Para documentar la API automáticamente
export☐ desactivado Endpoint POST /{tabla}/export que devuelve CSV desde la vista vis_* (requiere permiso sel) Cuando los usuarios necesitan exportar datos a Excel/CSV

⑨ Qué no editar — y qué sí personalizar

❌ Estos archivos se REEMPLAZAN en cada davgen generar — editarlos a mano significa perder los cambios al regenerar:
  • servicio/app/Http/Controllers/*Controller.php — Controllers delgados (solo llaman al Service)
  • servicio/app/Services/*Service.php — Services CRUD con auth+2FA (BaseService)
  • servicio/routes/api.php y web.php — rutas de la API y health-check
  • 04-Frontend.../src/services/*Service.js — servicios JS de cada entidad
  • 04-Frontend.../src/pages/*.jsx — páginas CRUD generadas
  • SPs pcru* en la BD — se regeneran y aplican con aplicar_sps
✅ Estos archivos son seguros para personalizar — el generador no los sobreescribe:
  • Clases que extienden los Services: crea app/Services/Custom{Entidad}Service.php extendiendo {Entidad}Service y agrega la lógica de negocio ahí
  • SPs de dominio pag_* (confirmar, cancelar…): en 02-Base-de-datos/ — el generador no los toca
  • src/App.jsx — pantalla de login y navegación principal (se crea una vez; nunca se sobreescribe)
  • src/api.js y src/authService.js — configuración Axios y lógica de auth (se crean una vez)
  • Tablas tbl_seg_* — roles, permisos, menú y parámetros runtime (2FA, rate-limit, Google auth…)

Herramientas de diagnóstico

davgen verificar   # detecta qué archivos generados fueron editados (exit 0/1)
davgen comparar    # muestra el diff exacto entre lo generado y lo editado

Si verificar reporta archivos MODIFICADO y quieres conservar los cambios, extráelos antes de regenerar. Si solo quieres restaurar el código original, ejecuta davgen generar — las ediciones se respaldan en _backendGenerado/_respaldo-ediciones/.
